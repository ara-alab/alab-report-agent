# MVP 구현 계획

MES/ERP 데이터를 조회·분석해 기업 서식 보고서를 자동 기안하는 AI Agent의 MVP 범위와 구현 계획

## 1. 목표

| 항목 | 내용 |
| --- | --- |
| 과제 | MES/ERP 연계형 지능형 보고서 기안 AI Agent |
| 목표 수준 | 핵심기능 3~5개와 End-to-End Workflow 1개가 안정적으로 동작하는 MVP |
| 개발 기간 | 업무일 5일 |
| 핵심 가치 | 자연어 요청 → 데이터 자동 조회 → 분석 → 서식 기안 → 근거 검증을 하나의 흐름으로 수행 |

## 2. 설계 원칙

| 항목 | 원칙 |
| --- | --- |
| 편집 화면 | 목업 HTML 지면 유지, 직접 편집은 최소화하고 상세 수정은 Agent 대화로 처리 |
| 프런트 | `public/report-mockup/index.html` 유지, 신규 로직은 별도 JS 파일로 분리 |
| 서버 | 같은 Next.js 앱의 API route에 Agent·조회·저장·출력 기능 추가 |
| LLM | Anthropic 호출 계층·모델 구성 |
| 데이터 | MySQL 기반 가상 MES 스키마, 테이블·데이터 추가가 쉬운 구조 |
| 데이터 조회 | 사전 정의 조회 함수 우선, 부족하면 LLM이 읽기 전용 SQL 생성 |
| 수치 산출 | 수치는 코드로 계산, LLM은 서술 작성·수정만 담당 |
| 서식 | 목업 서식(`weekly-summary.html`, `data-brief.html`)에서 출발, LLM이 서식 수정·신규 작성 가능 |
| 문서 출력 | HTML 지면·브라우저 인쇄(PDF) 기본, HWPX/DOCX는 별도 출력 엔진 |
| 실행 환경 | 로컬 개발, 시연은 로컬과 기존 배포 구성 모두 대응 |

## 3. 샘플 계정

| 계정 | 역할 | 주 사용 흐름 |
| --- | --- | --- |
| 생산기술부 김도현 과장 | 생산 보고 기안자 | 생산실적 보고서 요청·대화 수정 |
| 품질보증팀 담당자 | 품질 보고 기안자 | 불량 로그 중심 품질 보고서 요청 |
| 이상훈 부장 | 검토·승인자 | 하위 보고서 검토, 통합 보고서 작성, 근거·정합성 확인 |

- 실제 로그인 없이 타이틀바 계정 칩에서 계정 전환
- 계정별로 기안자 정보·결재선·기본 서식·조회 가능 테이블 범위를 다르게 적용
- 조회 범위는 SQL 가드의 계정별 허용 테이블 목록으로 제한

## 4. 생성 흐름

| 흐름 | 구분 | 동작 |
| --- | --- | --- |
| 대화로 시작 | 메인 | 자연어 요청 → Agent가 데이터 판단·조회·분석 → 서식까지 자동 결정해 바로 기안 |
| 템플릿으로 시작 | 메인 | 자연어 요청 → Agent가 대화로 추천 서식 카드 제시 → 사용자 선택 → 조회·분석·기안 |
| 보고서 통합 | 확장 | Agent가 생성·저장한 보고서 선택 → 저장된 구조화 데이터로 통합 보고서 기안 |

- 대화로 시작: 목업의 근거 원천 선택 카드 단계를 Agent 자동 판단으로 대체
- 템플릿으로 시작: `templates/index.json`의 고정 추천·적합도를 Agent 추천으로 대체
- 보고서 통합: 원천을 일일 보고서 JSON에서 저장된 Agent 보고서로 교체

## 5. 시연 시나리오

| 단계 | 사용자 | Agent·시스템 |
| --- | --- | --- |
| ① 요청 | 대화 입력란에 자연어로 보고서 요청 | 기간·대상·보고서 유형·필요 KPI를 구조화 출력으로 추출 |
| ② 조회 | 조회 계획과 진행 상황 확인 | 조회 함수 tool 호출, 부족하면 SQL 생성 후 실행 |
| ③ 분석 | KPI 요약과 이상 항목 확인 | 달성률·증감률·불량률(PPM)·가동률 계산, 규칙 기반 이상 판정, 원인 서술 작성 |
| ④ 기안 | 서식 자동 결정 또는 추천 서식 선택 후 초안 확인 | 서식 키와 분석 결과 매핑, 수치는 계산값 그대로, 서술 칸만 LLM이 작성 |
| ⑤ 수정 | "불량 원인 부분 더 자세히" 같은 대화 지시 | 섹션 단위 재작성, 필요 시 서식 자체 수정·추가 |
| ⑥ 검증 | 수치 선택 시 근거 쿼리·원본 행과 정합성 배지 확인 | 수치별 출처 기록, 보고서 수치와 원본 대조 |
| ⑦ 저장 | 보고서 저장 | 본문·KPI 값·분자/분모·수치별 출처를 구조화해 저장 |
| ⑧ 통합 | 검토·승인자가 저장 보고서를 골라 통합 보고서 요청 | 합계 값에서 비율 재계산, 통합 수치 → 하위 보고서 → MES 원본 순으로 근거 연결 |
| ⑨ 출력 | 인쇄·PDF 저장, HWPX/DOCX 저장 | 브라우저 인쇄, 이식한 출력 엔진으로 파일 생성 |

## 7. Agent tool

| tool | 역할 |
| --- | --- |
| `list_datasets` / `describe_table` | 사용 가능한 테이블과 컬럼 의미 조회 |
| `query_*` | 사전 정의 집계 조회, 결과에 출처 ID 부여 |
| `run_sql` | 조회 함수로 부족할 때 SQL 생성·실행, 가드 통과분만 실행 |
| `analyze_kpi` | KPI 계산·이상 판정, 결과는 코드 산출값 |
| `recommend_templates` | 요청에 맞는 서식 후보와 추천 사유 제시 |
| `draft_report` | 서식 키 매핑과 서술 작성, 지면 생성 |
| `revise_section` | 지정 섹션 재작성 |
| `edit_template` | 서식 수정·신규 작성 |
| `save_report` / `list_reports` | 보고서 저장, 저장 보고서 목록 조회 |
| `merge_reports` | 저장 보고서의 구조화 데이터로 통합 보고서 기안 |

## 8. 일정

| 일차 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1일차 | 로컬 MySQL·스키마·시드, DB 접속, 조회 함수 2~3개, LLM 호출 계층, Agent route 골격 | 조회 결과가 API로 반환되고 LLM 스트림이 화면 로그에 표시됨 |
| 2일차 | Agent 루프·tool 연결, SQL 가드, 스키마 카탈로그, KPI·이상 판정, 샘플 계정 | 자연어 요청 → 조회 → KPI 요약이 대화창에 표시됨 |
| 3일차 | 서식 레지스트리, 키 매핑, 서술 생성, 메인 흐름 2종 연동, 보고서 저장 | 요청 하나로 보고서 초안이 지면에 생성·저장됨 |
| 4일차 | 섹션 재작성, 서식 수정·작성, 근거 추적 패널, 정합성 검증, 보고서 통합 | 대화 지시로 수정되고 통합 보고서까지 근거·검증 결과가 표시됨 |
| 5일차 | 하위 보고서 사전 생성, HWPX/DOCX 출력, 통합 점검, 성능 측정, 시연 리허설, 배포 확인 | 시연 시나리오가 로컬·배포 환경에서 반복 실행됨 |

## 9. 목표 성능과 측정

| 평가항목 | 목표 | 측정 방법 |
| --- | --- | --- |
| 데이터 조회 성공률 | 95% | 시연 요청 세트 실행 시 tool 호출 오류·빈 결과가 아닌 비율 |
| 필수항목 자동작성률 | 90% | 서식별 필수 키 중 값이 채워진 비율 |
| 원본 데이터-보고서 수치 일치율 | 95% | 근거 검증 모듈의 수치 대조 통과 비율, 통합 보고서 포함 |
| Template Mapping 정확도 | 90% | 서식 키별 기대 원천·값 정답표와의 일치 비율 |

- 측정 결과는 시연 화면 또는 별도 리포트로 제시
